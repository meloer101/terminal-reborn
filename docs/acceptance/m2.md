# M2 验收记录 · 状态与即时回复（Claude）→ MVP

日期：2026-10-14 · 环境：macOS 26.3、Claude Code 2.1.299

## 自动化

| 项 | 结果 |
|---|---|
| `npm run check`（typecheck + lint + vitest） | 通过，553 个用例 |
| `npm run test:e2e`（终端、侧栏状态、选项条、⌘K、hooks 单元级 e2e） | 通过，37 / 37（6 个真实 agent 用例默认跳过） |
| `TR_E2E_AGENTS=claude npx playwright test hooks` | 通过 3 / 3（hooks 注入、GUI 作答、TUI 作答释放挂起的 hook） |
| `TR_E2E_AGENTS=claude npx playwright test mvp`（只通过界面操作） | 通过 2 / 2 |

MVP 用例的流程：输入栏发送 → Claude 请求 Bash 权限 → 侧栏变为「等你处理」并置顶、选项条出现 → 点「允许一次」→ 命令执行、文件写出 → 会话标题变为首条 prompt → 状态回到「空闲」；随后 AskUserQuestion 在选项条点 Green → Claude 回答 GREEN。

## 集成中修复

- 「等你处理」改由权限请求 / 提问本身触发：Claude 的 `Notification(permission_prompt)` 比 PermissionRequest 晚约 6 秒，之前侧栏要等这么久才变色。
- 会话标题默认取首条 prompt（PRD F2），不再一直显示「Claude Code」。
- 主题选择会记住，手动选深色 / 浅色后不再被系统外观覆盖；侧栏「跳转到…」打开 ⌘K。

## 已知限制

- 两个同时需要确认的工具调用会互相顶替，较早的那个回退到终端里的原生确认框。
- 用户自己在 alias 里追加 `--settings` 会让我们的 hooks 失效（只认最后一个），需要 PRD §6.2 的深合并 wrapper。
- 用户默认的 auto 模式下，无害的 Bash 不会触发权限请求，这是 Claude 的行为。
- Codex 的 hooks 在 M3。
